# Veintitrés PR que sólo existían en Git

## Objetivo

Cerrar DOC-002 reconstruyendo desde Git y GitHub qué entró entre las PR #39 y
#61, qué de aquello sigue vigente hoy, y devolver a `docs/` la condición de
fuente fiable. **Arqueología, no relleno.**

## Base

`main` en `e04f0e6f681e30b6fb493f6f312a0d61bbbb7dde` (PR #74), árbol limpio.
Rama de trabajo `docs/close-doc-002`. Documentación únicamente: ni `src/`, ni
`tests/`, ni dependencias, ni workflows.

## Metodología

Jerarquía de confianza, en este orden: **merge commit y diff real → código de
`main` → pruebas → cuerpo de la PR → documentación contemporánea**. La bóveda no
se usó como prueba de nada.

Para cada PR se leyeron metadatos (`gh pr view`), ficheros tocados y cuerpo, y
después se **comprobó contra el código actual** si la decisión seguía viva. Esa
comprobación es lo que separa «era cierto entonces» de «es cierto hoy», y es
donde aparecieron las sustituciones.

## Lo primero que se cayó: la premisa del propio DOC-002

DOC-002 afirmaba que las veintitrés PR «no están recogidas en ningún documento».
**Es falso, y se comprueba en un comando**: `git diff` de los merge commits de
#39, #40 y #41 sobre `docs/02-decisiones.md` devuelve 85, 55 y 117 líneas
añadidas, con seis decisiones —D-064 a D-069—. Esas tres PR sí se documentaron
en su momento.

Y su agrupación orientativa tenía dos errores de atribución: **#51 no es «aviso
de tienda»** —es el inestable del selector de Favoritos— y **#42 no es
«integridad de pruebas»** —es encaje a 320 px y estado de tiendas—.

## Por qué siete decisiones y no veintitrés

Agrupando por evolución coherente en vez de por unidad de entrega:

| Nueva | Agrupa | Motivo |
| --- | --- | --- |
| **D-078** | #43, #49, #58 | Tres pasos de un mismo criterio de color del armazón |
| **D-079** | #50, #54 | Dos defectos distintos del mismo arranque |
| **D-080** | #52 | Decisión aislada |
| **D-081** | #45 (+#46, #51) | Un criterio y dos aplicaciones suyas |
| **D-082** | #47 (+#48) | La #48 es del panel, no de la identidad; va como nota |
| **D-083** | #59 | Decisión aislada |
| **D-084** | #40, #57 | Datos y rótulo de la misma superficie |

Las sustituidas **no** recibieron D nueva: se etiquetaron en la decisión que las
reemplazó (D-075, D-076, D-077) y se narraron en el registro. Crear una entrada
«vigente» para un diseño muerto habría sido justo el error que DOC-002 pedía
evitar.

## Contradicciones encontradas dentro de la propia documentación

- **D-065 decía «vigente» mientras D-068 decía reemplazarla.** Se resuelve
  distinguiendo el principio —la app no monta la portada web, que sigue— de la
  composición —que la reemplazaron D-068, D-076 y D-077—.
- **D-068 seguía rotulando «Mis compras».** Desde la #57 el rótulo es
  «Compras»: `appnav.purchases` vale `'Compras'` **en castellano**, y tiene su
  traducción propia en los otros cuatro diccionarios.

- Las 23 PR inventariadas y **citadas por número** en el registro; comprobado con

- Ninguna motivación inventada: donde el diff y el cuerpo no explican el porqué,
